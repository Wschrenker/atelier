# Ablauforganisation

Werner bestimmt Richtung und Wahrheit. Hermes macht daraus eine sichere, ganze Arbeitskette. Claude Code bearbeitet nur die einzelne technische Werkstück-Aufgabe. Tests beweisen technischen Zustand. CLO 3D / Nessel beweisen oder korrigieren die fachliche Wirklichkeit.

## Die ganze Ordnung – und welche Frage jedes Ding beantwortet

| Rang / Rolle | Ding | Es beantwortet diese Frage |
|---:|---|---|
| **1** | **Werner, ausdrücklich im Jetzt** | **Was wollen wir jetzt wirklich? Was gilt, was wird geändert, was wird gestoppt?** |
| **2** | **Aktueller Chat / aktueller Auftrag** | **Was ist der konkrete nächste Gesprächs- oder Arbeitsauftrag?** |
| **3** | **`SOUL.md`** | **Wie sollen Hermes und Claude mit Werner, Unsicherheit, Überlastung, Ideen und Verantwortung umgehen?** |
| **4** | **Aktive SSOT** | **Was ist für diese fachliche Sache aktuell verbindlich wahr: Ziel, Entscheidung, Quelle, Grenze, offener Punkt?** |
| **5** | **`C:\ATELIER\AGENT.md`** | **Welche projektweiten Grenzen gelten in ATELIER, und welche Bereiche sind aktiv bzw. geschützt?** |
| **6** | **Lokales `AGENT.md`** | **Wofür ist genau dieser Ordner zuständig, was darf hier hinein, und welche direkten Unterordner gehören dazu?** |
| **7** | **`HERMES.md`** | **Wie übersetzt Hermes Wahrheit in einen sicheren Auftrag, wie prüft und integriert er Ergebnisse?** |
| **8** | **`CLAUDE.md`** | **Wie soll Claude Code in diesem Bereich technisch arbeiten: Scope, erlaubte Dateien, Tests, Bericht?** |
| **9** | **`README.md`** | **Was ist dieser Ordner, wo beginne ich, und welche aktiven Dokumente sind wichtig?** |
| **10** | **Quellen / Belege** | **Worauf stützt sich eine fachliche Aussage: Buchseite, Bild, Formel, Messung, Entscheidung?** |
| **11** | **Tests / technische Prüfungen** | **Funktioniert der Code unter den ausdrücklich geprüften technischen Bedingungen?** |
| **12** | **CLO 3D** | **Ergibt die fachliche Konstruktion digital ein plausibles, kontrollierbares Kleidungsstück?** |
| **13** | **Nessel / reale Anprobe** | **Funktioniert die Konstruktion tatsächlich am Körper, im Material und beim Nähen?** |

## Git steht daneben als Nachweis-Schicht

Git ist **nicht über oder unter Werner**. Es begleitet alle Ebenen als kontrollierbares Gedächtnis.

| Git-Ding | Es beantwortet diese Frage |
|---|---|
| **Working Tree** | **Woran wird gerade gearbeitet, was ist noch ein unbestätigter Kandidat?** |
| **Diff** | **Was genau wurde gegenüber dem letzten Stand verändert?** |
| **Commit** | **Welcher technische Stand wurde bewusst als prüfbarer Zeitpunkt festgehalten?** |
| **Branch** | **Welche getrennte Entwicklungsrichtung wird gerade verfolgt?** |
| **Historie** | **Wie und wann kamen wir zu einem früheren Stand oder einer Änderung?** |
| **Tag** *(erst später bei echtem Bedarf)* | **Welcher feste Stand gehört zu einem bestimmten CLO- oder Nessel-Versuch?** |

## Die zentrale Fragekette

```text
Werner:
    Was wollen wir?

SOUL.md:
    Wie arbeiten wir dabei sicher und menschlich?

SSOT:
    Was gilt fachlich?

AGENT.md:
    Wo gehört die Arbeit hin und welche Grenzen gelten?

HERMES.md:
    Wie wird daraus ein sicherer, prüfbarer Schritt?

CLAUDE.md:
    Wie baut der technische Arbeiter diesen begrenzten Schritt?

Tests:
    Ist der Code technisch korrekt?

CLO 3D:
    Ist das Ergebnis digital fachlich plausibel?

Nessel:
    Ist es in der Wirklichkeit tragfähig?

Git:
    Was wurde wann tatsächlich verändert, geprüft und festgehalten?
```
